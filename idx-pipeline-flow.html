The daily-ingestion pipeline, end to end

A cron fires one root task; asynq workers fan out, fetch from external sources, upsert into Postgres and an object store, and chain derived tasks. An MCP HTTP server reads the results. Redis is the decoupling bus between every stage.

The two halves

The pipeline splits cleanly into a write side (asynq workers populating Postgres and R2 on a schedule) and a read side (an MCP HTTP server exposing that data as JSON over a token-authed REST surface). They share only the database — workers never call the MCP server, and the MCP server never enqueues tasks. That separation is what lets ingestion run unattended while a separate consumer (an LLM tool client) queries the results.

Write side · task chain

  • pipeline:daily — root; fans out 3 ingest tasks, failures decoupled
  • idx:stock_summary — IDX EOD → daily_prices, then chains anomaly detection
  • idx:announcements — IDX filings → disclosures (status pending)
  • rss:ingest — RSS → news + ticker match; raw XML claim-check to R2
  • detect:anomalies — liquidity-gated (min ADTV); chains filter + broker summary
  • filter:disclosures — 3-layer filter over pending disclosures; chains extract per passing row
  • extract:disclosure — PDF download → R2 → text extraction
  • idx:broker_stock_summary — IPOT fetch per anomalous ticker

Read side · MCP endpoints

  • get_market_anomalies
  • list_idx_disclosures
  • read_idx_disclosure
  • get_ticker_news
  • get_broker_summary
  • get_pipeline_status

All six handlers currently return 501 Not Implemented — the routes and use-case wiring exist, the response bodies don't yet. That's the next layer of work.

Reliability layers worth knowing

Three mechanisms keep the pipeline from silently losing days. Idempotency sits at two layers: DB upserts (re-running a date overwrites, not duplicates) and asynq TaskID dedup keyed by {type}:{date} — a re-enqueue of the same date hits ErrTaskIDConflict and is skipped. Self-heal recovers archived tasks (retries exhausted, usually a transient Cloudflare 403): it deletes the archived entry to free the ID, then re-enqueues with a 30-minute delay so the block has time to lift. Decoupled fan-out means an announcements or RSS failure is logged, not fatal — the stock-summary chain still runs.

Two binaries

  • mcp-server — long-running: asynq server + scheduler + self-heal + HTTP read API + asynq dashboard on :8081
  • enqueue-daily — one-shot CLI: enqueue a single task by date, or bulk-backfill a date range synchronously (no asynq)

Storage

  • Redis — asynq queue + scheduler state
  • Postgres — all structured results (10 tables)
  • R2 / MinIO — S3-compatible; raw XML + PDFs + extracted text. Optional: nil store leaves rows pending; filter re-enqueues them next run
